macOS · per-process clock control

Move one program's clock, not the machine's.

A dyld shim that offsets, scales or pins the wall clock inside a single process, to one nanosecond of resolution. Built for running several WSJT-X instances side by side, each on its own independently adjustable clock, while the rest of the Mac keeps perfect time.

How it works

The shim is a dylib injected with DYLD_INSERT_LIBRARIES. It uses dyld's __DATA,__interpose section, which rewrites bind targets in every loaded image except the one declaring the interpositions — so the library calls the real functions by their ordinary names. 

out = anchor + (in − anchor) × rate + offset

anchor is that clock's value at injection, so rate diverges from the moment the program starts rather than from the epoch.

NSDate, Swift's Date and CFAbsoluteTimeGetCurrent come along transitively, because CoreFoundation reads the clock through gettimeofday. Interposing CF as well double-shifts it — a real bug this project hit, and removed.

Install

No dependencies. Builds universal (arm64 + x86_64) and ad-hoc signs itself.

# build the shim, the probe and the control tool
make

# shift one program back 90 minutes
bin/timeshift --offset -90m -- ./yourprogram

# or run its clock at 2× from launch
bin/timeshift --offset 250ms --rate 2 -- ./yourprogram

# adjust a *running* process through a shared control file
bin/timeshift-ctl init /tmp/rig1.ctl --offset 0
bin/timeshift --control /tmp/rig1.ctl -- ./yourprogram &
bin/timeshift-ctl nudge /tmp/rig1.ctl --offset 100ms

Will your target accept it?

dyld strips every DYLD_* variable from a restricted process silently — the program just runs on real time and nothing tells you why. Check first: bin/timeshift-check <binary-or-.app>

worksPrograms you build yourself — no signing changes needed
worksThird-party binaries without the hardened runtime
worksHardened apps you re-sign a copy of, via timeshift-resign
neverApple platform binaries under SIP — /System, /usr/bin, /bin. /bin/date cannot be shimmed.
neversetuid binaries, or anything carrying entitlements

Running several WSJT-X instances

WSJT-X ships Developer ID–signed with the hardened runtime, so it rejects the shim as delivered. Make an injectable copy once, then launch that copy — one bundle serves every instance, each with its own --rig-name and its own control file. 

bin/timeshift-resign /Applications/wsjtx.app "/Applications/wsjtx shift.app"
bin/timeshift --offset -0.4s -- "/Applications/wsjtx shift.app/Contents/MacOS/wsjtx"

The menubar app

make menubar builds ab6a-timeShift.app: a menubar controller that starts each configured rig, and gives every one a slider and ±0.1 s steps that move that instance's clock live, while it runs.

Gotchas that cost real time

  • Launch the inner executable, not open -a. open hands off to launchd, which starts the app in a clean environment where DYLD_INSERT_LIBRARIES never arrives.
  • Grant the microphone to the launcher. macOS attributes a child's mic request to the responsible process — the menubar app or your terminal, not WSJT-X.
  • Leave monotonic alone. WSJT-X aligns its 15-second slots off the wall clock; shifting mach_absolute_time only perturbs Qt's timers.

Limits, stated plainly

  • Nothing outside the process moves. File timestamps, timer firing, log timestamps and certificate validity checked in other processes all stay on real time.
  • Your log moves with the clock. ADIF QSO times, PSK Reporter spots and ALL.TXT record the shifted time. Correcting a wrong clock — that's the point. Experimenting — log to a copy.
  • Re-signing has costs. It invalidates notarization and resets the app's TCC grants. timeshift-resign always works on a copy and never touches the original.
  • A narrow unshifted window at startup. Clock reads from inside libSystem's own initializers pass through untransformed — deliberately. That context has no TLS, a non-re-entrant os_once, and no malloc zone yet; all three crash a shim that tries to do real work there.
  • Offsets jump, they don't slew. Lowering the offset makes the program's wall clock run backwards. For a gradual machine-wide correction instead, the call you want is adjtime(2).
